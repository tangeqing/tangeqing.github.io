# 吉他和弦琶音练习器开发文档

## 1. 项目名称

**Guitar Arpeggio Trainer｜吉他和弦琶音练习器**

---

## 2. 项目目标

开发一个可在本地直接运行的吉他和弦琶音练习器。

项目采用纯前端方式开发，不需要服务器、不需要数据库、不需要安装依赖。用户双击 `index.html` 即可使用。

该工具用于练习：

- 不同根音和不同和弦类型的琶音；
- 固定把位与跨把位琶音；
- 和弦音在吉他指板上的位置；
- 当前音对应的弦号、品位、音名和和弦级数；
- 单和弦、和弦进行及循环练习；
- 不同速度、节奏型和音符时值下的琶音演奏。

用户会提供一张参考图片。参考图片主要用于表达以下视觉和交互目标：

1. 顶部显示当前和弦名称；
2. 中间显示类似动态 TAB 六线谱的音符序列；
3. 当前播放位置有明显的播放指针或高亮；
4. 随播放进度，当前音符向前推进；
5. 当前和弦切换时，TAB 上方同步显示新的和弦名称。

参考图片只作为视觉与交互参考，不要求逐像素复刻。

## 3. 开发方式与技术约束

### 3.1 技术栈

必须使用：

- HTML5
- CSS3
- 原生 JavaScript ES6+
- Canvas 或 SVG
- Web Audio API
- localStorage

不得使用：

- React
- Vue
- Angular
- Node.js
- npm
- TypeScript
- 在线 CDN
- 在线字体
- 在线音频资源
- 依赖网络加载的第三方库
- 后端服务
- 数据库

### 3.2 本地运行要求

项目必须满足：

1. 双击 `index.html` 可以直接运行；
2. 断网状态下可完整使用；
3. 不依赖本地服务器；
4. 不出现跨域资源错误；
5. 所有资源均保存在项目目录内；
6. Chrome、Edge、Safari 最新版本可正常运行；
7. 页面应适配桌面端，兼顾平板端；
8. 首次点击“开始播放”后初始化 Web Audio API，以符合浏览器自动播放限制。

## 4. 用户使用流程

完整使用流程如下：

1. 用户选择调弦方式；
2. 用户选择根音；
3. 用户选择和弦类型；
4. 用户选择练习模式；
5. 用户选择把位范围或 CAGED 把位；
6. 用户设置速度、拍号、音符时值和每个和弦持续时间；
7. 用户点击“生成练习”；
8. 系统计算和弦音；
9. 系统寻找指定把位内的可用指板位置；
10. 系统生成符合演奏习惯的琶音路径；
11. TAB 区域显示完整练习序列；
12. 指板显示所有当前和弦音；
13. 用户点击“开始”；
14. 节拍器和琶音音频开始播放；
15. TAB、指板、当前音信息同步高亮；
16. 到达练习结尾后，根据设置停止或循环；
17. 用户可以保存当前方案，之后直接加载。

## 6. 音乐理论数据模型

## 6.1 音高类别

内部统一使用 0～11 表示十二平均律音高类别：

```javascript
C  = 0
C# = 1
D  = 2
Eb = 3
E  = 4
F  = 5
F# = 6
G  = 7
Ab = 8
A  = 9
Bb = 10
B  = 11
```

程序内部可以统一使用数字计算，界面显示时根据用户偏好显示升号或降号。

### 6.2 同音异名

必须正确处理：

- C# / Db
- D# / Eb
- F# / Gb
- G# / Ab
- A# / Bb

显示规则：

1. 降号调优先显示降号；
2. 升号调优先显示升号；
3. 用户可以手动切换“升号显示”与“降号显示”；
4. 和弦级数显示独立于音名显示。

## 7. 调弦系统

第一版最终结果必须包含以下调弦：

- 标准调弦：E A D G B E
- Drop D：D A D G B E
- 全音降调：D G C F A D
- 半音降调：Eb Ab Db Gb Bb Eb

另外提供“自定义调弦”：

- 六根弦分别选择音名；
- 支持设置实际八度；
- 可以保存自定义调弦；
- 自定义调弦存入 localStorage。

标准调弦的 MIDI 值：

```javascript
6弦 E2 = 40
5弦 A2 = 45
4弦 D3 = 50
3弦 G3 = 55
2弦 B3 = 59
1弦 E4 = 64
```

界面中，1 弦必须显示在最上方，6 弦显示在最下方。

## 10. 把位系统

必须支持三种选择方式。

### 10.1 固定品位范围

用户选择：

- 最低品：0～23
- 最高品：1～24

要求：

- 最高品必须大于最低品；
- 默认范围为 5～9 品；
- 支持常用快捷范围：
  - 0～4
  - 1～5
  - 3～7
  - 5～9
  - 7～11
  - 8～12
  - 10～14
  - 12～16
  - 15～19
  - 全指板 0～24

### 10.2 CAGED 把位

支持：

- C 型
- A 型
- G 型
- E 型
- D 型

CAGED 模式下：

- 根据当前根音自动定位形状；
- 显示该形状覆盖的主要品位；
- 根音位置必须突出；
- 可以选择“严格限制在形状内”或“允许附近扩展 2 品”。

### 10.3 自动把位

系统根据当前和弦和练习方向，自动寻找最易演奏的区域。

自动把位评分应考虑：

- 品位跨度；
- 根音数量；
- 可用和弦音数量；
- 是否包含完整和弦结构；
- 是否需要大幅跨弦；
- 是否出现连续重复音；
- 是否过多使用空弦；
- 是否适合当前音序。

## 14. 可演奏路径生成算法

该功能是项目核心，不能只按照音高排序或随机选点。

## 14.1 候选位置生成

对每一个目标和弦音，在指定品位范围内生成所有候选位置：

```javascript
{
  string: 6,
  fret: 8,
  midi: 48,
  pitchClass: 0,
  noteName: "C",
  degree: "1"
}
```

### 14.2 路径约束

路径必须遵循：

1. 相邻音尽量不超过 5 品跨度；
2. 默认不允许一次跨越超过 3 根弦；
3. 上行时 MIDI 音高不得下降；
4. 下行时 MIDI 音高不得上升；
5. 固定把位模式下不得超出用户设置范围；
6. 避免连续使用同一音高；
7. 避免不必要的同音异弦跳转；
8. 尽量减少左手大幅横向移动；
9. 尽量保持每根弦 1～3 个音；
10. 高把位下允许合理换把；
11. 和弦切换时优先选择共同音或最近音；
12. 不得生成物理上明显不合理的跳跃路径。

### 14.3 路径评分

为候选路径计算成本：

```text
总成本 =
品位移动成本
+ 跨弦成本
+ 方向违反成本
+ 重复音成本
+ 同音换弦成本
+ 超出把位成本
+ 换把成本
+ 不完整和弦成本
+ 不自然手型成本
```

推荐初始权重：

```javascript
fretDistanceWeight = 2.0
stringDistanceWeight = 1.5
directionViolationWeight = 100
duplicatePitchWeight = 8
samePitchDifferentStringWeight = 5
positionShiftWeight = 4
outOfRangeWeight = 1000
```

允许根据测试结果调整。

### 14.4 算法实现

可采用：

- 动态规划；
- 最短路径；
- 分层图搜索；
- Beam Search。

不得对所有位置进行无限穷举，以免页面卡顿。

### 14.5 无法生成时

如果当前条件无法生成有效路径：

- 显示清晰原因；
- 提供一键放宽把位；
- 提供一键允许跨把位；
- 提供一键减少音序长度；
- 不得静默失败；
- 不得生成明显错误路径。

## 19. 左手指法建议

系统应为每个音提供建议手指：

- 1：食指
- 2：中指
- 3：无名指
- 4：小指

基础规则：

1. 当前把位最低主品位优先分配食指；
2. 向上每品依次分配 2、3、4 指；
3. 五品跨度时允许伸展；
4. 换把时重新计算手型；
5. 空弦显示 0；
6. 指法只是建议，界面允许隐藏。

系统不需要模拟全部复杂古典吉他指法，但不得明显违反常见左手逻辑。

## 26. 数据校验与错误处理

必须处理：

- 最低品大于最高品；
- 和弦没有可用位置；
- 自定义音序包含无效级数；
- 自定义调弦格式错误；
- BPM 非法；
- 导入 JSON 损坏；
- localStorage 已满；
- AudioContext 创建失败；
- 浏览器不支持某项 API；
- 生成路径超时；
- 当前条件无法生成可演奏路径。

错误提示必须明确，不使用只显示“发生错误”之类的模糊文案。

## 27. 性能要求

1. 参数修改后生成路径应尽量在 300ms 内完成；
2. 全指板复杂和弦应在 1 秒内完成；
3. UI 播放动画尽量保持 60 FPS；
4. 音频调度不得明显漂移；
5. 运行 30 分钟不得出现计时器不断累积；
6. 暂停、停止后必须清理未播放事件；
7. 不得重复创建无限数量的 AudioNode；
8. 页面切换到后台再回来后，应能正确恢复或停止，不得时间错乱。
